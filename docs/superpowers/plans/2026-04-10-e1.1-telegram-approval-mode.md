## Task 1: lib/approval.sh::ks_approval_resolve_reference()

**Files:**
- Modify: `~/.openclaw/skills/knowledge-sync/lib/approval.sh` (adicionar funcao)

**Spec:** secao 4.1 (assinatura, inputs, codigos de erro)

> **Critico:** esta funcao e a base de tudo. `canonical approve`, `canonical reject` e `status <id>` vao depender dela. Os 5 codigos de erro (`not_found`, `ambiguous`, `expired`, `executed`, `rejected`) sao o contrato com o Vox via mensagens BLOQUEADO.

- [ ] **Step 1: Adicionar a funcao no final de lib/approval.sh**

```bash
cat >> ~/.openclaw/skills/knowledge-sync/lib/approval.sh <<'RESOLVE_EOF'

# Resolve uma referencia (last, prefix de 8+ chars, ou UUID completo) para um approval_id real
# Args: $1 = referencia
# Output (se ok): approval_id em stdout, exit 0
# Output (se erro): "ERROR <code>" em stderr, exit != 0
# Codes:
#   not_found            - referencia nao bate com nenhum approval
#   ambiguous:<id1>,<id2>,... - prefix bate com 2+ approvals (em pending)
#   expired:<id>         - bate, mas TTL excedido (granted-stale OU pending-stale)
#   executed:<id>        - bate, mas ja foi executado
#   rejected:<id>        - bate, mas ja foi rejeitado
ks_approval_resolve_reference() {
  local ref="$1"

  if [[ -z "$ref" ]]; then
    echo "ERROR not_found" >&2
    return 1
  fi

  if [[ ! -f "$KS_EVENTS_FILE" ]]; then
    echo "ERROR not_found" >&2
    return 1
  fi

  # Coletar todos os approval_ids ja vistos (qualquer estado)
  local all_pending all_granted all_executed all_rejected
  all_pending="$(jq -rc 'select(.event=="canonical_approval_pending") | {id: .payload.approval_id, ts: .ts}' "$KS_EVENTS_FILE" 2>/dev/null)"
  all_granted="$(jq -rc 'select(.event=="canonical_approval_granted") | .payload.approval_id' "$KS_EVENTS_FILE" 2>/dev/null | sort -u)"
  all_rejected="$(jq -rc 'select(.event=="canonical_approval_rejected") | .payload.approval_id' "$KS_EVENTS_FILE" 2>/dev/null | sort -u)"
  all_executed="$(jq -rc 'select(.event=="canonical_committed" or .event=="canonical_pushed" or .event=="canonical_marker_created") | .payload.approval_id // empty' "$KS_EVENTS_FILE" 2>/dev/null | sort -u)"

  # Determina conjunto de candidatos baseado na referencia
  local candidates
  if [[ "$ref" == "last" ]]; then
    # last = todos os pendentes (a logica de "1 unico ou bloquear" e tratada abaixo)
    candidates="$(echo "$all_pending" | jq -rc '.id')"
  else
    # Prefix matching: minimo 8 chars (validado pelo regex no caller, mas defensivo aqui)
    if [[ ${#ref} -lt 8 ]]; then
      echo "ERROR not_found" >&2
      return 1
    fi
    # Match contra approvals em qualquer estado (pending, granted, executed, rejected)
    local all_ids
    all_ids="$( (echo "$all_pending" | jq -rc '.id'; echo "$all_granted"; echo "$all_executed"; echo "$all_rejected") | sort -u | grep -v '^$')"
    candidates="$(echo "$all_ids" | grep "^${ref}" || true)"
  fi

  # Filtrar vazios
  candidates="$(echo "$candidates" | grep -v '^$' || true)"

  # Contar
  local count
  count="$(echo "$candidates" | grep -c '^' 2>/dev/null || echo 0)"
  [[ -z "$candidates" ]] && count=0

  if (( count == 0 )); then
    echo "ERROR not_found" >&2
    return 1
  fi

  if (( count > 1 )); then
    # Ambiguidade: mostrar primeiros 8 chars de cada
    local ids_short
    ids_short="$(echo "$candidates" | head -5 | awk '{print substr($0, 1, 8)}' | tr '\n' ',' | sed 's/,$//')"
    echo "ERROR ambiguous:${ids_short}" >&2
    return 1
  fi

  # 1 unico candidato - verificar estado
  local id="$candidates"

  # Ja executado?
  if echo "$all_executed" | grep -qx "$id"; then
    echo "ERROR executed:${id}" >&2
    return 1
  fi

  # Ja rejeitado?
  if echo "$all_rejected" | grep -qx "$id"; then
    echo "ERROR rejected:${id}" >&2
    return 1
  fi

  # Verificar TTL
  local pending_ts
  pending_ts="$(echo "$all_pending" | jq -rc --arg id "$id" 'select(.id==$id) | .ts' | head -1)"
  if [[ -n "$pending_ts" ]]; then
    local pending_epoch now_epoch elapsed
    pending_epoch="$(date -u -d "$pending_ts" +%s 2>/dev/null || echo 0)"
    now_epoch="$(date -u +%s)"
    elapsed=$((now_epoch - pending_epoch))
    if (( elapsed > KS_APPROVAL_TTL_SECONDS )); then
      echo "ERROR expired:${id}" >&2
      return 1
    fi
  fi

  # Tudo ok - retornar o ID
  echo "$id"
  return 0
}
RESOLVE_EOF
```

    # Aceita: <UUID>, <prefix de 8+ chars>, "last"

          exit 3 ;;
        expired:*)
          ks_err_id="${ks_err_code#expired:}"
          echo "BLOQUEADO: approval ${ks_err_id:0:8} expirou" >&2
          exit 3 ;;
        executed:*)
          ks_err_id="${ks_err_code#executed:}"
          echo "BLOQUEADO: approval ${ks_err_id:0:8} ja foi executado" >&2
          exit 3 ;;
        rejected:*)
          ks_err_id="${ks_err_code#rejected:}"
          echo "BLOQUEADO: approval ${ks_err_id:0:8} ja foi rejeitado" >&2
          exit 3 ;;
        *)
          echo "BLOQUEADO: erro desconhecido: $ks_err_code" >&2
          exit 3 ;;
      esac
    fi

    # CONTRATO ESTAVEL: imprime o approval_id resolvido na PRIMEIRA LINHA do stdout
    echo "$ks_resolved_id"

    # Concede o approval
    ks_approval_grant "$ks_resolved_id"

## Task 3: scripts/pending.sh - FIFO + limit 10 + --json

**Files:**
- Modify: `~/.openclaw/skills/knowledge-sync/scripts/pending.sh` (reescrever)

**Spec:** secao 4.3 (formato JSON, regras de ordem/limit, output humano)

- [ ] **Step 1: Substituir o conteudo de scripts/pending.sh**

```bash
cat > ~/.openclaw/skills/knowledge-sync/scripts/pending.sh <<'PENDING_EOF'
#!/usr/bin/env bash
# pending - lista approvals canonicos pendentes
# Output: humano (default) ou JSON (--json)
# Ordem: FIFO (mais antigo primeiro)
# Limit: 10
set -euo pipefail
SKILL_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
source "$SKILL_DIR/lib/common.sh"
source "$SKILL_DIR/lib/events.sh"
source "$SKILL_DIR/lib/approval.sh"

LIMIT=10
JSON_MODE=false

while [[ $# -gt 0 ]]; do
  case "$1" in
    --json) JSON_MODE=true; shift ;;
    --limit) LIMIT="$2"; shift 2 ;;
    *) shift ;;
  esac
done

if [[ ! -f "$KS_EVENTS_FILE" ]]; then
  if $JSON_MODE; then
    echo '{"count": 0, "total": 0, "limit": '"$LIMIT"', "items": []}'
  else
    echo "Sem approvals pendentes."
  fi
  exit 0
fi

# Identificar approvals pending: tem canonical_approval_pending, sem granted/rejected/executed depois
# Tambem filtrar expirados (TTL excedido)
now_epoch="$(date -u +%s)"

# Coletar todos os approval_ids ainda pending
pending_data="$(jq -rc --argjson now "$now_epoch" --argjson ttl "$KS_APPROVAL_TTL_SECONDS" '
  select(.event=="canonical_approval_pending")
  | {
      approval_id: .payload.approval_id,
      action: .payload.action,
      context: .payload.context,
      created_at: .ts,
      created_epoch: (.ts | strptime("%Y-%m-%dT%H:%M:%SZ") | mktime)
    }
  | select(($now - .created_epoch) <= $ttl)
' "$KS_EVENTS_FILE" 2>/dev/null)"

if [[ -z "$pending_data" ]]; then
  if $JSON_MODE; then
    echo '{"count": 0, "total": 0, "limit": '"$LIMIT"', "items": []}'
  else
    echo "Sem approvals pendentes."
  fi
  exit 0
fi

# Filtrar os que ja foram resolvidos (granted/rejected/executed)
resolved_ids="$(jq -rc 'select(.event=="canonical_approval_granted" or .event=="canonical_approval_rejected" or .event=="canonical_committed" or .event=="canonical_pushed" or .event=="canonical_marker_created") | .payload.approval_id // empty' "$KS_EVENTS_FILE" 2>/dev/null | sort -u)"

# Construir lista de pendentes ainda nao resolvidos, ordenada FIFO
items_json="$(echo "$pending_data" | jq -sc --argjson now "$now_epoch" --arg resolved "$resolved_ids" '
  . as $all
  | ($resolved | split("\n")) as $resolved_list
  | [
      $all[]
      | select(.approval_id as $id | $resolved_list | index($id) | not)
      | {
          approval_id: .approval_id,
          short_id: .approval_id[0:8],
          action: .action,
          context: .context,
          created_at: .created_at,
          age_seconds: ($now - .created_epoch)
        }
    ]
  | sort_by(.created_at)
')"

total="$(echo "$items_json" | jq 'length')"

# Aplicar limit
visible_items="$(echo "$items_json" | jq -c --argjson n "$LIMIT" '.[:$n]')"
visible_count="$(echo "$visible_items" | jq 'length')"

if $JSON_MODE; then
  jq -nc \
    --argjson count "$visible_count" \
    --argjson total "$total" \
    --argjson limit "$LIMIT" \
    --argjson items "$visible_items" \
    '{count: $count, total: $total, limit: $limit, items: $items}'
  exit 0
fi

# Saida humana
if (( visible_count == 0 )); then
  echo "Sem approvals pendentes."
  exit 0
fi

if (( total > visible_count )); then
  echo "Pendentes ($visible_count de $total) - use o CLI para ver todos:"
else
  echo "Pendentes ($visible_count de $total):"
fi
echo ""

echo "$visible_items" | jq -r '.[] |
  "[\(.short_id)] \(.action)\n" +
  "  \(if .context.files then "arquivos: " + (.context.files | join(", ")) else "" end)\n" +
  "  ha \(if (.age_seconds / 60 | floor) < 1 then "<1 min" elif (.age_seconds / 60 | floor) < 60 then "\(.age_seconds / 60 | floor) min" else "\(.age_seconds / 3600 | floor) h" end)\n"'

echo ""
echo "Use /approve <id-curto> ou /reject <id-curto>"
PENDING_EOF
chmod +x ~/.openclaw/skills/knowledge-sync/scripts/pending.sh
```

source "$SKILL_DIR/lib/approval.sh"

JSON_MODE=false
REF=""

while [[ $# -gt 0 ]]; do
  case "$1" in
    --json) JSON_MODE=true; shift ;;
    *) REF="$1"; shift ;;
  esac
done

# ========================================
# Modo especifico: status <ref>
# ========================================
if [[ -n "$REF" ]]; then
  # Resolver referencia para approval_id (mas tratar erros como output, nao falha)
  resolved=""
  state="not_found"
  raw_id=""

  if [[ "$REF" == "last" ]]; then
    # Para "last", pega o pending mais recente que ainda existe (qualquer estado)
    raw_id="$(jq -rc 'select(.event=="canonical_approval_pending") | .payload.approval_id' "$KS_EVENTS_FILE" 2>/dev/null | tail -1)"
  else
    # Prefix matching contra TODOS os approval_ids vistos
    if [[ ${#REF} -ge 8 ]]; then
      all_ids="$(jq -rc 'select(.event=="canonical_approval_pending") | .payload.approval_id' "$KS_EVENTS_FILE" 2>/dev/null | sort -u)"
      matches="$(echo "$all_ids" | grep "^${REF}" || true)"
      match_count="$(echo "$matches" | grep -c '^' 2>/dev/null || echo 0)"
      [[ -z "$matches" ]] && match_count=0
      if (( match_count == 1 )); then
        raw_id="$matches"
      fi
    fi
  fi

  if [[ -z "$raw_id" ]]; then
    state="not_found"
  else
    # Verificar estado
    has_executed="$(jq -rc --arg id "$raw_id" 'select((.event=="canonical_committed" or .event=="canonical_pushed" or .event=="canonical_marker_created") and .payload.approval_id == $id)' "$KS_EVENTS_FILE" 2>/dev/null | head -1)"
    has_rejected="$(jq -rc --arg id "$raw_id" 'select(.event=="canonical_approval_rejected" and .payload.approval_id == $id)' "$KS_EVENTS_FILE" 2>/dev/null | head -1)"
    has_granted="$(jq -rc --arg id "$raw_id" 'select(.event=="canonical_approval_granted" and .payload.approval_id == $id)' "$KS_EVENTS_FILE" 2>/dev/null | head -1)"

    pending_event="$(jq -rc --arg id "$raw_id" 'select(.event=="canonical_approval_pending" and .payload.approval_id == $id)' "$KS_EVENTS_FILE" 2>/dev/null | head -1)"
    pending_ts="$(echo "$pending_event" | jq -r '.ts' 2>/dev/null || echo "")"
    action="$(echo "$pending_event" | jq -r '.payload.action' 2>/dev/null || echo "")"
    context_json="$(echo "$pending_event" | jq -c '.payload.context' 2>/dev/null || echo "{}")"

    now_epoch="$(date -u +%s)"
    pending_epoch="$(date -u -d "$pending_ts" +%s 2>/dev/null || echo 0)"
    age_seconds=$((now_epoch - pending_epoch))
    ttl_remaining=$((KS_APPROVAL_TTL_SECONDS - age_seconds))

    if [[ -n "$has_executed" ]]; then
      state="executed"
    elif [[ -n "$has_rejected" ]]; then
      state="rejected"
    elif (( age_seconds > KS_APPROVAL_TTL_SECONDS )); then
      state="expired"
    elif [[ -n "$has_granted" ]]; then
      state="granted"
    else
      state="pending"
    fi
  fi

  if $JSON_MODE; then
    jq -nc \
      --arg id "$raw_id" \
      --arg short "${raw_id:0:8}" \
      --arg state "$state" \
      --arg action "$action" \
      --argjson context "$context_json" \
      --arg created_at "$pending_ts" \
      --argjson age "${age_seconds:-0}" \
      --argjson ttl_remaining "${ttl_remaining:-0}" \
      '{
        approval_id: (if $id == "" then null else $id end),
        short_id: (if $short == "" then null else $short end),
        state: $state,
        action: (if $action == "" or $action == "null" then null else $action end),
        context: $context,
        created_at: (if $created_at == "" then null else $created_at end),
        age_seconds: $age,
        ttl_remaining_seconds: $ttl_remaining
      }'
    exit 0
  fi

  # Saida humana especifica
  if [[ "$state" == "not_found" ]]; then
    echo "Approval $REF: nao encontrado"
    exit 0
  fi

  echo "Approval ${raw_id:0:8}"
  echo "Estado: $state"
  [[ -n "$action" && "$action" != "null" ]] && echo "Action: $action"
  if [[ -n "$pending_ts" ]]; then
    age_min=$((age_seconds / 60))
    echo "Criado: $pending_ts (ha ${age_min} min)"
  fi
  if [[ "$state" == "pending" || "$state" == "granted" ]] && (( ttl_remaining > 0 )); then
    ttl_min=$((ttl_remaining / 60))
    echo "TTL restante: ${ttl_min} min"
  fi
  exit 0
fi

# ========================================
# Modo geral: status (sem ref)
# ========================================
if [[ "$JSON_MODE" == "true" ]]; then
  ks_state_read
  exit 0
fi

state="$(ks_state_read)"
if [[ "$state" == "{}" || -z "$state" ]]; then
  echo "knowledge-sync - state vazio. Rode 'knowledge-sync refresh' primeiro."
  exit 0
fi

cat <<HEAD
knowledge-sync - bevox-knowledge

  Branch:           $(echo "$state" | jq -r '.branch.current // "?"')
  Tracking:         $(echo "$state" | jq -r '.branch.tracking // "?"')
  Head:             $(echo "$state" | jq -r '.branch.head_sha // "?" | .[0:10]')
  Remote head:      $(echo "$state" | jq -r '.branch.tracking_head_sha // "?" | .[0:10]')
  Sync:             ahead $(echo "$state" | jq -r '.branch.ahead'), behind $(echo "$state" | jq -r '.branch.behind')
  Working tree:     $(echo "$state" | jq -r 'if .working_tree.clean then "clean" else "dirty" end')
  Git operations:   $(echo "$state" | jq -r 'if (.git_operations.merge_in_progress or .git_operations.rebase_in_progress or .git_operations.cherry_pick_in_progress) then "in progress" else "none" end')
  Conflicts:        $(echo "$state" | jq -r 'if .conflicts.potential then "POTENTIAL: \(.conflicts.reason // "")" else "none" end')

  Drafts:           $(echo "$state" | jq -r '.draft_branches | length') active
HEAD

echo "$state" | jq -r '.draft_branches[]? | "    - \(.name)  (head \(.head_sha[0:10]), \(.ahead_of_main) ahead of main)"'

cat <<TAIL

  Health:           $(echo "$state" | jq -r '.health.overall' | tr 'a-z' 'A-Z')
TAIL

echo "$state" | jq -r '.health.issues[]? | "    - \(.code) [\(.severity)] since \(.since)"'

cat <<TIME

  Last fetch:       $(echo "$state" | jq -r '.last.fetch_at // "never"')
  Last commit:      $(echo "$state" | jq -r '.last.commit_at // "never"') ($(echo "$state" | jq -r '.last.commit_sha // "?"'))
  Last push:        $(echo "$state" | jq -r '.last.push_at // "never"')
  Watcher last ran: $(echo "$state" | jq -r '.watcher.ran_at // "never"') ($(echo "$state" | jq -r '.watcher.duration_ms // 0')ms)

## Telegram Command Mode

Quando voce recebe uma mensagem do Telegram em DM do Bernard (sender id `<TELEGRAM_USER_ID>`)
que casa com um dos regex abaixo, voce DEVE entrar em modo comando.

### Comandos reconhecidos

| Regex | Acao |
|---|---|
| `^/approve\s+(last\|[a-f0-9]{8,}(?:-[a-f0-9-]+)?)$` | Aprovar e executar |
| `^/reject\s+(last\|[a-f0-9]{8,}(?:-[a-f0-9-]+)?)(?:\s+--reason\s+(.+))?$` | Rejeitar |
| `^/pending$` | Listar pendentes |
| `^/status(?:\s+([a-f0-9]{8,}(?:-[a-f0-9-]+)?))?$` | Estado geral ou de approval especifico |

### Regras inviolaveis

1. **Comandos tem precedencia sobre conversa natural.** Se a mensagem casa qualquer regex acima, entre em modo comando e NAO responda como agente conversacional.

2. **Parse e estrito.** Nao tente interpretar `aprova ai`, `aceita o ultimo`, `pode aprovar o commit`, ou variacoes em portugues. So a barra explicita.

3. **Sender autorizado.** Aceite os comandos APENAS em DM do Bernard (sender id `<TELEGRAM_USER_ID>`). Em grupos, mesmo com mention, **ignore** os comandos `/approve`, `/reject`, `/pending`, `/status`.

4. **Voce roteia, a skill valida.** Voce so resolve o regex e roda o comando da skill via bash tool. NAO interprete IDs, NAO resolva "last", NAO valide TTL - tudo isso fica na skill.

5. **Resposta curta e operacional.** 4 estados possiveis:
   - **Sucesso:** `OK: <action> aprovado e executado. <SHA/tag>`
   - **Rejeitado:** `REJEITADO: <id>` (com motivo se houver)
   - **Bloqueado:** `BLOQUEADO: <razao>` - policy ou estado invalido
   - **Falhou:** `FALHOU: <razao tecnica>` - erro de execucao

### Workflow exato

#### `/approve <ref>`

1. Roda: `knowledge-sync canonical approve <ref>`
2. Se `exit != 0`: responde `BLOQUEADO: <stderr da primeira linha>` e PARA
3. Se `exit == 0`: captura o approval_id resolvido (PRIMEIRA LINHA do stdout - contrato estavel)
4. Roda: `knowledge-sync canonical execute <approval_id>`
5. Se `exit != 0`: responde `FALHOU: <stderr da primeira linha>`
6. Se `exit == 0`: responde combinando os dois marcos:
   ```
   APROVADO: <id-curto>
   EXECUTADO: <output>
   ```

A resposta final deve ter os dois marcos (approval concedido + acao executada) visualmente claros.

#### `/reject <ref> [--reason "<motivo>"]`

1. Roda: `knowledge-sync canonical reject <ref> [<motivo>]`
2. Resposta padrao: `REJEITADO: <id>` (com motivo se houver) ou `BLOQUEADO: <razao>`

#### `/pending`

1. Roda: `knowledge-sync pending --json`
2. Parseia o JSON
3. Formata para Telegram (lista compacta com short_id, action, idade)
4. Se vazio: `Sem approvals pendentes.`
5. Se houver mais que 10: incluir `(mostrando 10 de N - use CLI para ver todos)`

#### `/status [<ref>]`

1. Sem ref: roda `knowledge-sync status` e repassa o output ja formatado
2. Com ref: roda `knowledge-sync status <ref> --json`, parseia e formata os campos relevantes (state, action, age, ttl_remaining)

### O que NAO fazer

- NAO tente "ajudar" reformulando approvals
- NAO invente approval_ids
- NAO sugira a re-solicitacao de approvals expirados (Bernard decide isso manualmente)
- NAO responda comandos de mutacao (`/commit`, `/push`, `/draft`, `/snapshot`) - eles NAO existem no escopo do bot
- NAO aceite comandos de outros senders, mesmo se forem do allowlist do Telegram
- NAO use `knowledge-sync pending` sem `--json` para parsing automatico - depender do texto humano e fragil
